# wyo

**wyo** is a free, open-source program that a marketplace seller installs on a server the seller owns or rents. With the seller's own
marketplace keys it reads the seller's orders from Wildberries (more marketplaces follow) and shows them in one list. Only when the
seller fills in a setting for it (planned, named «External API») does it also exchange orders, labels, statuses and marking codes with
an external fulfilment centre, through an open, documented format. Apart from the marketplaces, it sends nothing anywhere else. It is
licensed under Apache-2.0.

## Что это

**wyo** — бесплатная программа с открытым кодом для продавца на маркетплейсах. Продавец устанавливает её на сервер, который принадлежит ему
или который он арендует, и вводит свои собственные ключи маркетплейсов. Программа сама, периодически, читает заказы продавца с
маркетплейса и показывает их одним списком. Первый маркетплейс — Wildberries; остальные появятся позже.

Программа в том числе может работать с внешними фулфилмент-центрами. Это включается одной настройкой, которая будет называться «External
API». В неё продавец впишет адрес и ключ системы фулфилмент-центра. Формат обмена открыт и описан в `docs/fulfilment-centre-api.md`,
поэтому любой фулфилмент-центр может его поддержать. Через этот формат программа будет передавать заказы и этикетки, а получать обратно
статусы, коды маркировки и документы передачи.

## Чего программа не делает никогда

Эти три правила записаны в конституции проекта (`.specify/memory/constitution.md`), и у каждого есть проверка, которая не даёт их нарушить.

- **Не общается ни с кем, кроме маркетплейсов, пока настройка «External API» не заполнена** (правило R3). Программа не отправляет
  статистику использования и не проверяет обновления так, чтобы передавать сведения об установке. Это нужно, чтобы продавец мог быть
  уверен: пока он сам ничего не включил, данные его магазина не уходят никуда, кроме самих маркетплейсов.
- **Ключ маркетплейса не покидает сервер продавца** (правило R4). Программа не отправляет его фулфилмент-центру, не записывает в журнал и
  после сохранения показывает только его последние четыре символа. Это нужно, потому что правила Wildberries запрещают передавать личный
  токен третьим лицам и использовать его в облачных сервисах: он должен жить на собственной или арендованной продавцом инфраструктуре.
  Поэтому сотрудники фулфилмент-центра не должны устанавливать программу за продавца и не должны хранить его ключи.
- **Ничего не скрывает от маркетплейса** (правило R5). В каждом запросе программа называет себя и свою версию, держится в пределах
  допустимого числа запросов, которое указал маркетплейс, и ждёт, сколько он скажет. Она не маскирует запросы, не использует прокси и не
  меняет адреса.

## Состояние

**Программа пока не устанавливается; установщик появится в следующем выпуске.** Сейчас в этом репозитории готова основа для разработки:
правила для разработчиков и ИИ-агентов, проверки качества, библиотека элементов интерфейса, поддельные Wildberries и поддельный
фулфилмент-центр для тестов. Пошаговые инструкции для продавца — как установить программу, как обновить её, как подключить Wildberries и как
включить «External API» — будут написаны в тех выпусках, где эти возможности появятся, и будут проверяться тестом, чтобы в них не попало
ничего, чего в программе нет.

## Для разработчика

Всё для начала работы — какие инструменты нужны, ежедневные команды, где что лежит и как управлять поддельными маркетплейсами — описано в
`docs/development.md`. Правила для людей и ИИ-агентов, которые меняют код, — в `AGENTS.md`; правила проекта — в
`.specify/memory/constitution.md`; планы — в `.agents/plans/`.
