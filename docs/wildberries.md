# wyo и Wildberries: какие запросы отправляет wyo

Эта страница — для инженера продавца: для того, кто хочет сам проверить, к каким адресам Wildberries обращается wyo, какими запросами,
как часто и в каких пределах, и что из этого остаётся в журнале. Как подключить аккаунт Wildberries по шагам, написано в `README.md`,
раздел 7.

**Откуда взяты факты.** Каждый факт о Wildberries здесь взят из документов самого Wildberries; где документ молчит, так и написано: «не
подтверждено документами Wildberries». Источники:

- **Файлы описания** программного доступа Wildberries (OpenAPI), скачанные 17.11.2026 без изменений и лежащие в `api/wildberries/`
  (адреса — в `api/wildberries/README.md`): `01-general.yaml`, `02-items.yaml`, `03-orders-fbs.yaml`, `12-reports.yaml` со страницы
  `https://dev.wildberries.ru/api/swagger/yaml/ru/`. Разбор — `.agents/research/wildberries-official-description-files-check-2026-11-17.md`,
  раздел 2 (таблица методов и пределов).
- **Статьи о токене**, прочитанные 18.11.2026: «Как создать, обновить или удалить токен WB API»
  (`https://seller.wildberries.ru/instructions/ru/ru/material/how-to-create-update-or-delete-a-wb-api-token`) и копии статей в
  `docs/marketplaces/`. Разбор — `.agents/research/wildberries-token-check-2026-11-18.md`.

Поведение wyo описано по коду: адаптер Wildberries — `internal/marketplace/wildberries/` (`wildberries.go` — список запросов и пределов,
`check.go`, `orders.go`, `feed.go`), движок синхронизации — `internal/sync/` (`engine.go` — расписание, `caller.go` — повторы и сроки,
`budget.go` — учёт пределов), журнал — `internal/journal/journal.go`, список разрешённых адресов — `internal/outbound/outbound.go`.

## Адреса

wyo обращается только к четырём адресам Wildberries, и только по `https://`. Других адресов Wildberries в списке разрешённых адресов wyo
нет (`internal/outbound/outbound.go`, назначение `marketplace`), и запрос на любой другой адрес wyo не отправит.

| Адрес                                    | Что там спрашивает wyo                                  | Источник                                                           |
| ---------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------ |
| `marketplace-api.wildberries.ru`         | проверка токена, склады, новые заказы FBS, их состояния | `03-orders-fbs.yaml`, `02-items.yaml`, `01-general.yaml` (`/ping`) |
| `marketplace-api-sandbox.wildberries.ru` | то же, но только для тестового токена (песочница)       | те же файлы, сервер с описанием «Sandbox»                          |
| `common-api.wildberries.ru`              | имя продавца                                            | `01-general.yaml`                                                  |
| `statistics-api.wildberries.ru`          | проверка категории «Статистика», лента заказов          | `12-reports.yaml`, `01-general.yaml` (`/ping`)                     |

Каждый запрос:

- **называет программу** заголовком `User-Agent: wyo/<версия> (+https://github.com/prankyman/wyo)` (`internal/outbound/outbound.go`,
  `UserAgent`), чтобы Wildberries видел, какая программа и какой версии к нему обращается. Требования называть себя в файлах описания
  Wildberries нет (это не подтверждено документами Wildberries); wyo делает это по своему правилу R5 (`.specify/memory/constitution.md`);
- **несёт токен в заголовке `Authorization`** как есть, потому что так велит Wildberries: «Добавляйте токен в заголовок запроса
  `Authorization`» (`01-general.yaml`, часть «Авторизация»). Токен берётся из зашифрованного хранилища только на время запроса;
- **ждёт ответа не дольше 30 секунд**, не идёт за перенаправлением (ответ 3xx считается отказом) и никогда не идёт через прокси, даже если
  на сервере заданы переменные окружения прокси, потому что wyo ничего не скрывает от маркетплейса (правило R5).

Если сервер выпускает наружу только разрешённые адреса, разрешите исходящие соединения на порт 443 этих четырёх адресов (для тестового
токена достаточно `marketplace-api-sandbox.wildberries.ru`).

## Запросы

Все шесть запросов только читают. Список запросов адаптера — `Routes()` в `internal/marketplace/wildberries/wildberries.go`; движок
отказывается отправить запрос, которого нет в этом списке (`internal/sync/caller.go`, ошибка `ErrNotDeclared`).

| Задача в журнале    | Метод и путь                  | Адрес                               | Как часто                                                                                                              | Предел Wildberries для Персонального токена (период \| запросов \| интервал \| пачка) | Файл описания, метод                       |
| ------------------- | ----------------------------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------ |
| «Проверка ключа»    | `GET /ping`                   | `marketplace-api`, `statistics-api` | при добавлении и замене токена, раз в сутки, по кнопке «Проверить ключ сейчас»                                         | «30 сек \| 3 запроса \| 10 сек \| 99 запросов»                                        | `01-general.yaml`, `getPing`               |
| «Проверка ключа»    | `GET /api/v1/seller-info`     | `common-api`                        | вместе с проверкой токена, кроме тестового (у песочницы этого метода нет)                                              | «1 мин \| 1 запрос \| 1 мин \| 10 запросов»                                           | `01-general.yaml`, `getV1SellerInfo`       |
| «Склады»            | `GET /api/v3/warehouses`      | `marketplace-api`                   | раз в сутки и после каждой проверки сохранённого токена (ежедневной и по кнопке «Проверить ключ сейчас»)               | «1 мин \| 300 запросов \| 200 мс \| 20 запросов»                                      | `02-items.yaml`, `getV3Warehouses`         |
| «Новые заказы»      | `GET /api/v3/orders/new`      | `marketplace-api`                   | каждые 30 минут и по кнопке «Обновить»                                                                                 | «1 мин \| 300 запросов \| 200 мс \| 20 запросов»                                      | `03-orders-fbs.yaml`, `getV3OrdersNew`     |
| «Состояния заказов» | `POST /api/v3/orders/status`  | `marketplace-api`                   | каждые 30 минут и по кнопке «Обновить»; до 1 000 номеров в запросе; ни одного запроса, если незакрытых заказов FBS нет | «1 мин \| 300 запросов \| 200 мс \| 20 запросов»                                      | `03-orders-fbs.yaml`, `postV3OrdersStatus` |
| «Лента заказов»     | `GET /api/v1/supplier/orders` | `statistics-api`                    | каждые 30 минут и по кнопке «Обновить»; страница за страницей, пока лента не ответит `[]`                              | «1 мин \| 1 запрос \| 1 мин \| 10 запросов»                                           | `12-reports.yaml`, `getV1SupplierOrders`   |

Пояснения к таблице:

- **`/ping`** — метод самого Wildberries, который проверяет, действителен ли токен и совпадает ли его категория с адресом
  (`01-general.yaml`). wyo спрашивает его на адресе категории «Маркетплейс» всегда и на адресе категории «Статистика», если она отмечена в
  токене. Тестовый токен спрашивается только в песочнице.
- **`POST /api/v3/orders/status`** — запрос, а не изменение: в теле wyo передаёт номера своих незакрытых заказов FBS, а Wildberries
  отвечает их состояниями. В файле описания метод помечен `x-readonly-method: true` (`03-orders-fbs.yaml`, строка 761 копии от
  17.11.2026), как и остальные пять методов таблицы. Методы, которые меняют данные, помечены там `false`; ни один из них wyo в этом выпуске
  не вызывает.
- **Лента заказов** читается дальше от сохранённой метки: первый запрос — с момента добавления аккаунта, каждый следующий — с поля
  `lastChangeDate` последней строки прошлого ответа, как велит Wildberries; пустой ответ `[]` значит, что прочитано всё (`12-reports.yaml`,
  описание параметра `dateFrom`). Время в ленте — московское (UTC+3). Wildberries обновляет ленту «раз в 30 минут» и хранит заказ 90 дней;
  в ленте может не быть заказов, «по которым не подтверждена оплата». Лента нужна для заказов FBO и для вида, бренда и размера товара; её
  строка связывается с заказом FBS по полю `srid`, которое, по словам Wildberries, «равно `rid` в ответах методов сборочных заданий».
- **Тестовый токен** работает только с песочницей. У песочницы нет ленты заказов и метода `seller-info` (в файлах описания у них нет
  адреса «Sandbox»), поэтому тестовый аккаунт читает только заказы FBS. Для песочницы `03-orders-fbs.yaml` пишет: «максимум 1 запрос в
  секунду суммарно для всех методов Маркетплейса»; для тестового токена `01-general.yaml` даёт «1 минута \| 150 запросов \| 200
  миллисекунд \| 10 запросов». Какой из двух пределов песочница соблюдает на деле, не подтверждено документами Wildberries; wyo держится
  более строгого — одного запроса в секунду.
- **Расписание:** заказы — каждые 30 минут, склады и проверка токена — раз в сутки (`internal/sync/engine.go`, `Jobs`); момент каждой
  задачи сдвинут на случайное время до 10 секунд, чтобы много установок не обращались в одну и ту же секунду. Кнопка «Обновить» запускает
  чтение заказов всех работающих аккаунтов сразу, но срабатывает не чаще раза в 5 минут (`RefreshEvery`).

**Сколько это запросов.** Одно чтение одного аккаунта с 25 незакрытыми заказами FBS: 1 запрос новых заказов, 1 запрос состояний и 1–2
запроса ленты — 3–4 запроса раз в 30 минут, то есть 144–192 в сутки, плюс за сутки 3 запроса проверки токена и 2 запроса складов (по своему расписанию и после ежедневной проверки токена).
Предел методов заказов FBS — 300 запросов в минуту, поэтому wyo расходует его ничтожную часть.

## Чего wyo не вызывает никогда

- **Запрос данных покупателя** `POST /api/v3/orders/client` (`03-orders-fbs.yaml`, `postV3OrdersClient`): он отдаёт имя и телефон
  покупателя. Для него даже не создан программный код: в настройках генерации `api/codegen/wildberries-orders.cfg.yaml` этого метода нет, а
  в списке запросов адаптера его тоже нет, так что движок его не отправит.
- **Любой запрос, меняющий данные** в кабинете Wildberries: подтверждение и отмена заказов, этикетки, коды маркировки, поставки. Код для
  части из них уже создан из файлов описания, потому что они понадобятся следующей версии, но в списке запросов адаптера этого выпуска их
  нет.
- **Данные покупателя из ответов** не сохраняются: адрес и комментарий покупателя в заказе FBS и поля `countryName`, `oblastOkrugName`,
  `regionName` строки ленты отбрасываются на границе адаптера и не попадают ни в базу, ни в журнал, ни в записи программы.

## Пределы, ожидание и повторы

- **Учёт пределов.** Для каждого аккаунта, каждой группы пределов и каждого адреса wyo ведёт счёт запросов, которые можно отправить сейчас
  (`internal/sync/budget.go`). Начальные числа — пределы из таблицы выше. Каждый ответ поправляет счёт по заголовку
  `X-Ratelimit-Remaining` («количество запросов, которое можно выполнить на данный момент без пауз», `01-general.yaml`). Ответ с кодом
  4xx в категории «Маркетплейс» считается за 10 запросов, потому что так считает Wildberries: «Один запрос с кодами ответов `4XX`
  учитывается как 10 запросов» (`01-general.yaml`). Для остальных групп файлы этого не говорят, и такой ответ считается за один.
- **Ответ 429** («слишком много запросов»): wyo ждёт столько секунд, сколько сказано в заголовке `X-Ratelimit-Retry` (1 секунду, если
  заголовка нет), и удваивает ожидание, если 429 повторяется. До 30 секунд wyo ждёт на месте; дольше — откладывает запрос до следующего
  чтения.
- **Повторы.** Запрос, на который не пришёл ответ или пришла ошибка сервера (5xx), повторяется через 1 и через 3 секунды, каждая пауза
  сдвинута случайно на пятую часть в любую сторону. Ответ 4xx не повторяется никогда, потому что повтор получит тот же отказ.
- **Состояние аккаунта.** Ответ 401 («Пользователь не авторизован», `01-general.yaml`) переводит аккаунт в «Ключ не принят», и wyo
  перестаёт его читать до замены токена или удачной проверки. Пять неудачных чтений подряд переводят аккаунт в «Нет связи».

## Что записывает журнал

На каждый отправленный запрос — одна строка таблицы `request_journal` (`internal/store/migrations/0002_accounts_orders_journal.sql`),
которую показывает страница «Журнал запросов»:

| Поле                       | Что в нём                                                                                                                               |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `at`                       | время отправки                                                                                                                          |
| `account_id`               | аккаунт, по токену которого отправлен запрос                                                                                            |
| `marketplace`              | код маркетплейса (`wildberries`)                                                                                                        |
| `method`                   | метод: `GET` или `POST`                                                                                                                 |
| `path`                     | путь без параметров; каждая часть пути с цифрой заменена на `{id}`, например `/api/v3/supplies/WB-GI-1234567` → `/api/v3/supplies/{id}` |
| `status`                   | код ответа (`0`, если ответа не было)                                                                                                   |
| `outcome`                  | итог одним из шести слов: `done`, `limited`, `refused`, `server_error`, `no_connection`, `key_refused`                                  |
| `error_code`, `error_text` | код и текст ошибки; текст не длиннее 500 знаков, токен и всё, что похоже на ключ или пароль, стёрто                                     |
| `duration_ms`              | сколько миллисекунд шёл запрос                                                                                                          |
| `job`                      | задача, отправившая запрос: проверка ключа, склады, новые заказы, состояния, лента или нажатие «Обновить»                               |

**Никогда в журнале нет** токена, параметров адреса и тел запросов и ответов (`internal/journal/journal.go`). Строки можно только
добавлять: изменение строки база данных отклоняет (триггер `request_journal_insert_only`). Каждую ночь, в случайную минуту между 03:00 и
04:00 по времени сервера, wyo удаляет строки старше 30 дней. Если строку не удалось записать, это попадает в записи программы и не меняет
исход самого запроса.
